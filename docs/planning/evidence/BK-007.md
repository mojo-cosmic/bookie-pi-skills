# BK-007 completion evidence

## Scope

Implemented the SPEC-002 production validator for one explicit filesystem vault. It consumes the BK-006 lossless loader and canonical SPEC-001 schemas, then validates manifest policy, Bookie/generic OKF records, local CommonMark links, current-tree relations and Decision lifecycle, Evidence resource containment, and exact-byte digests.

Git-base Decision retention, Activity/Evidence immutability, pinned target identity, Git tracking/submodules, and base resource changes remain BK-009.

## Files and behavior

- `packages/core/src/vault-validator.ts` orchestrates the public asynchronous `validateVault(root, options?)` API.
- Package-private modules isolate cancellation, deterministic diagnostics, filesystem snapshots/bounds, CommonMark parsing, internal models, and current-tree policy:
  - `vault-cancellation.ts`
  - `vault-diagnostics.ts`
  - `vault-filesystem.ts`
  - `vault-markdown.ts`
  - `vault-model.ts`
  - `vault-policy.ts`
- `packages/core/scripts/copy-schemas.mjs` copies canonical root schemas into `dist/schemas` during build; `packages/core/package.json` includes runtime assets and explicit Ajv, formats, CommonMark, and YAML dependencies.
- `packages/core/test/vault-validator.test.mjs` exercises examples, full vault fixtures, materialized policy fixtures, independent multi-error reporting, security races, package relocation, cancellation, limits, generic OKF, and redaction.
- SPEC-002, security architecture, toolchain, documentation index, and core README define the accepted public and failure contracts.

## Public contract

`validateVault()` returns:

- `valid`: true only when validation is complete and has no errors;
- `complete`: false when bounds, unreadable/torn required input, invalid/missing manifest policy, or diagnostic truncation prevents a complete claim;
- `diagnosticsTruncated`: specifically identifies diagnostic-cap exhaustion;
- deterministic static diagnostics and the resolved real root.

Cancellation consistently rejects with `AbortError`, including custom abort reasons, timeout signals, and late final-snapshot verification. Invalid programmer limits reject with `TypeError`; vault content failures return diagnostics.

Default limits are 64 KiB manifest, 1 MiB per Markdown file, YAML depth 64, 100,000 traversed entries, 50,000 concepts, 512 MiB aggregate Markdown bytes, 2 GiB streamed Evidence bytes, and 1,000 diagnostics. Callers may lower but not raise them through this API.

## Red evidence

The first focused test run failed before implementation because the validator API did not exist:

```text
SyntaxError: The requested module '../dist/index.js' does not provide an export named 'DEFAULT_MAX_VAULT_CONCEPTS'
ℹ tests 13
ℹ pass 12
ℹ fail 1
```

Subsequent failing regressions demonstrated and then fixed:

- duplicate CommonMark definitions were traversed backwards instead of using the first definition;
- invalid UTF-8 in reserved Markdown threw through the content API;
- an ancestor-directory symlink race allowed an outside concept to be parsed;
- in-place manifest changes after reading could still yield `valid: true`;
- Evidence metadata/content changes during streaming were not detected with high-resolution change time;
- schema-invalid Bookie records skipped `TYPE-ALLOWED` and `UID-UNIQUE` checks on otherwise trustworthy fields;
- an invalid manifest disabled fail-closed sensitivity redaction;
- an excluded Evidence resource symlink leaked its resource path through `VAULT-IO`;
- predecessor-only Decision links omitted `DECISION-SUPERSESSION`;
- manifest/concept size limits did not mark validation incomplete;
- cancellation propagated custom reasons or `TimeoutError` and was not checked during final snapshot verification;
- direct AST schema lookup depended on repository layout and failed after package relocation;
- direct Evidence reads buffered whole resources rather than streaming.

## Acceptance demonstrated

- Both complete valid vaults pass production validation.
- All five valid policy proposed trees pass.
- All 21 invalid current-tree policy cases emit their declared profile codes; the mixed base/current resource-byte case emits current-tree `EVIDENCE-DIGEST` without claiming a BK-009 immutability result.
- One run reports independent `CONCEPT-SCHEMA`, `MARKDOWN-LINK`, `RELATION-TARGET`, `EVIDENCE-RESOURCE`, and `EVIDENCE-DIGEST` findings.
- Schema-invalid Bookie candidates still enforce trusted path/type/UID policy while only schema-valid records may satisfy project/relation/support targets.
- Generic OKF concepts—including generic `Task`—remain outside Bookie policy unless they carry a `bookie` mapping.
- Inline links, images, used references, Unicode escapes, external schemes, fragments, duplicate definitions, traversal, and encoded separators cover the documented CommonMark boundary without rendering or fetching.
- Evidence hashing is incremental and exact; configured-root, real-root, size, symlink, metadata-race, aggregate-byte, missing, and digest cases fail closed.
- Every enumerated/read/hashed path retains ancestor and file snapshots through final validation. Device, inode, mode, size, nanosecond modify/change times, and realpath are rechecked.
- Excluded record paths, UIDs, titles, bodies, relation targets, local link targets, Evidence resource paths, and outside marker content do not appear in diagnostics.
- Diagnostic order and truncation are deterministic; incomplete and truncated states cannot appear valid.
- A real tarball is extracted to a relocated path, imports successfully, carries byte-identical canonical schemas, exposes no parser-specific public declarations, and validates the complete fixture without network installation.

## Assumptions and follow-ups

- `policy.exclude` is an anchored segment-glob omission boundary; invalid manifests cannot authorize exclusions, though parseable excluded sensitivity classes are still used for fail-closed diagnostic redaction.
- The 50,000-concept maximum is not precluded by count/entry limits and allows about 10 KiB aggregate Markdown per concept. Integrated 50,000-concept performance remains release-level SPEC-002 verification rather than a BK-007 claim.
- Node lacks a portable `openat` directory-handle API. The validator compensates with no-follow final opens plus retained ancestor/file identity and nanosecond timestamp snapshots before, after, and at final completion; detected races return `VAULT-IO` and `complete: false`.
- The generated schema copy is disposable package output; root `schemas/` remains authoritative.
- BK-008 must apply the same containment discipline inside atomic conflict-safe mutation windows.
- BK-009 must consume the 11 deferred base-sensitive policy cases without weakening current-tree results.

## Drift found and resolved

- Initial SPEC-002 wording would have reserved profile type names such as `Task`, contradicting SPEC-001 and ADR-0001; Bookie detection now requires a `bookie` mapping.
- Ordinary Markdown link behavior was underspecified; source files, link node forms, local/external resolution, percent encoding, fragments, queries, directories, and raw HTML are now explicit.
- `truncated` originally conflated diagnostic truncation and incomplete filesystem/resource validation; `complete` and `diagnosticsTruncated` now have separate meanings.
- The test-only fixture validator returned early after manifest failure and followed directory symlinks; production validation continues independent safe checks without reusing that oracle.
- The root schema layout was not relocatable as a core runtime dependency; build-time canonical asset copying plus a real package relocation smoke test resolves it without creating another tracked schema authority.
- No accepted ADR or product requirement was weakened or superseded.
