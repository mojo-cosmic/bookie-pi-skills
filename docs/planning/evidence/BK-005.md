# BK-005 completion evidence

## Scope

Completed Bookie profile 1.0 with a normative reference, compatibility and migration rules, a human-readable example vault containing every initial type, a schema-valid flow-style YAML vault, and isolated invalid Markdown vaults. SPEC-001 is Implemented but remains unverified until SPEC-002 consumes the contracts through production lossless loading and whole-vault/Git-base validation.

## Files and behavior

- `docs/reference/profile-v1.md` documents the manifest, common/type metadata, paths, Evidence, relations, stable validation codes, checkpoint behavior, authoring guidance, and exact major/minor migration behavior.
- `examples/vault/` now contains Project, Task, Document, Research, Decision, Activity, Evidence, and Person records with resolvable links/relations and an exact-byte captured resource.
- `fixtures/valid-vault/` uses YAML 1.2 flow-style JSON frontmatter so a generic parser can materialize and Ajv-validate every concept, including unknown-extension and Unicode-path boundaries.
- `fixtures/invalid-vaults/` isolates missing type, profile mismatch, manifest type exclusion, missing relation/resource, invalid Decision lifecycle, and multi-predecessor immutable correction behavior.
- `test/vault-fixtures.test.mjs` parses every manifest and concept with the generic `yaml` package, validates schemas and manifest policy, and checks type allowance, UIDs, project/relation/inverse/supersession boundaries, Evidence support/root/size/digest, and fixture expectations.
- `test/repository.test.mjs` resolves bundle-absolute Markdown links against the containing example, valid, or invalid vault.
- `yaml` is a test-only YAML 1.2 conformance reader; production round-trip library selection remains OQ-002.

## Red evidence

Before implementation, `node --test test/vault-fixtures.test.mjs` failed all four top-level tests:

```text
ℹ tests 4
ℹ pass 0
ℹ fail 4
```

The profile reference and vault fixture directories were missing, and the example contained only Project, Task, and Activity.

Review mutations then demonstrated that the first fixture oracle allowed manifest/profile/root/size drift, invalid Task supersession, malformed example timestamps, and a reserved-file mistake. Migration prose also conflicted with merged Activity/Evidence immutability. Added regressions failed before manifest-driven generic YAML validation, complete relation rules, legacy immutable migration handling, and invalid Markdown cases were implemented. A valid-vault bundle-absolute link also reproduced the repository link-root bug before its fix.

## Review corrections

Independent correctness and architecture reviews required and verified these corrections:

- parse and Ajv-validate both block-style example YAML and flow-style fixture YAML;
- validate `bookie.yaml` and drive type allowance, Evidence roots, and byte limits from it;
- reject logical duplicate relations, unsupported supersession, inverse/cardinality/UID mismatch, invalid Decision lifecycle, and multi-predecessor Activity/Evidence corrections;
- treat only `index.md` and `log.md` as reserved Markdown;
- preserve merged Activity/Evidence exact bytes and historical profile markers across major migrations, refusing targets that do not explicitly recognize legacy immutable schemas;
- distinguish secrets, which are never canonical, from sensitivity-excluded canonical records, which are omitted from derived operations;
- resolve absolute Markdown links from each containing vault root.

Final independent review approved the corrected BK-005 artifacts with no remaining blockers.

## Acceptance demonstrated

- A generic YAML 1.2 consumer parses every valid Markdown concept and manifest; Ajv validates every initial type.
- Both the human-readable example and machine-oriented valid vault contain all eight types, valid prefixed UIDs, complete project/target/support resolution, required inverses, and exact Evidence bytes.
- Valid boundaries include an unknown top-level extension and Unicode concept path.
- Invalid vaults isolate schema, manifest allow-list, relation, supersession, immutable-correction cardinality, and Evidence resource failures.
- Compatibility rules distinguish exact schemas, additive minor versions, breaking majors, read-only unknown minors, explicit migration, legacy immutable records, refusal behavior, and Git rollback.
- The complete profile reference links to normative schemas/specification and preserves the canonical/derived boundary.

## Assumptions and follow-ups

- JSON flow mappings are valid YAML 1.2 and intentionally make schema conformance deterministic; the separate example remains human-readable block-style YAML.
- The test-only `yaml` dependency does not settle OQ-002 because production mutation must additionally prove comment/order/unknown-field/multiline/body preservation.
- OQ-002 is now the next delivery gate; BK-006 remains Blocked and no implementation item is Ready.
- Destination adapters, runtime validation, and all service behavior remain outside SPEC-001.

## Drift found and resolved

- Initial migration prose would have required rewriting immutable profile markers; historical immutable schemas are now explicitly retained or migration refuses.
- Manifest `allowed_concept_types` was descriptive without enforcement; `TYPE-ALLOWED` now defines and tests its behavior without creating a centralized OKF registry.
- Initial authoring prose incorrectly grouped sensitivity-excluded canonical records with secrets; it now follows REQ-026.
- Repository absolute-link resolution was example-specific; it now respects every fixture vault boundary.
- No accepted ADR was contradicted or superseded.
