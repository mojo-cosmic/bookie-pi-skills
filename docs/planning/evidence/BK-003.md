# BK-003 completion evidence

## Scope

Added JSON Schema 2020-12 contracts for the common decoded OKF frontmatter and all initial Bookie concept types: Project, Task, Document, Research, Decision, Activity, Evidence, and Person. Added versioned positive, error, and boundary fixtures, including both Research scope forms and top-level OKF Evidence resource placement.

## Files and behavior

- `schemas/bookie-common.schema.json` validates required common metadata, recognized OKF provenance/trust/freshness shapes, prefixed-ULID syntax, calendar-valid UTC timestamps, media type essence, HTTP(S) evidence origins, and open extension fields.
- `schemas/types/*.schema.json` fixes each initial type and its required fields; Research requires exactly project or explicit vault-shared scope, and Evidence requires top-level `resource`.
- `fixtures/concepts/1.0/{valid,invalid}/` covers every initial type, project/shared Research, missing UID/resource, scope conflicts, workflow/lifecycle boundaries, timestamp boundaries, and evidence digest syntax.
- `test/concept-schema.test.mjs` meta-validates schemas, pins fixture errors to exact locations and missing properties, omits every required field, exercises every type, profile, and enum constant, checks known OKF shapes and wrong JSON types at nested locations, proves both usage-window forms, and covers media/origin attacks while retaining unknown extensions.
- `package.json` and `package-lock.json` add the maintained `ajv-formats` companion so URI syntax is asserted rather than hand-waved by a regex alone.
- `docs/specs/001-canonical-ledger.md`, `docs/architecture/data-model.md`, `docs/architecture/security.md`, downstream specifications, the backlog, and `docs/INDEX.md` record the accepted contracts and testable sensitivity-exclusion handoffs.

## Acceptance demonstrated

- Common metadata requires `type`, `title`, `status`, `generated`, and `bookie`; lifecycle remains independent from Bookie workflow state.
- Every required common/type field, every initial type constant, every lifecycle/workflow enum, wrong JSON types, missing/malformed UID, and UTC calendar/time boundaries have automated coverage.
- Research supports exactly one of project ownership or `bookie.scope: shared`; neither, both, and an unknown scope fail.
- Evidence requires top-level OKF `resource`, capture time, lowercase SHA-256, media type essence, and supported concepts. Bookie-only resource placement, punctuation-leading/control/wildcard/parameter media types, non-web/relative/credential-bearing origins, out-of-range numeric hosts/ports, and malformed percent escapes fail; valid trailing-dot IPv4 hosts and zero-padded in-range ports pass.
- Known OKF sources, source/generation/verification actors, verification events, freshness dates, and usage windows are structurally validated; every usage count has shared or per-source window context while unknown top-level, recognized-object, and `bookie` fields remain accepted for lossless SPEC-002 round trips.
- Relation vocabulary, target normalization, exact type-prefix mapping, resource containment, digest verification, Git-base immutability, and usage-window ordering remain runtime or BK-004/later work.

## Assumptions and follow-ups

- Correcting profile 1.0 is safe before merge because these concept schemas have not reached accepted `main` or a release. Once accepted, changing required placement or Research scope semantics is breaking and requires migration handling.
- `bookie.origin` intentionally permits HTTP(S) only, rejects embedded credentials, and remains untrusted syntax rather than fetch authorization.
- OQ-002, OQ-005, and OQ-007 remain unresolved; no decision was guessed across them.

## Drift found and resolved

- The first schema draft put Evidence `resource` under `bookie`, contrary to OKF and the accepted data model; it now uses the top-level OKF field.
- The data-model Task example used undeclared state `open`; it now uses `in_progress`.
- BK-004 still claimed lifecycle/state enum work delivered by BK-003; its scope now names only the remaining relation, exact-prefix, and cross-file policy work.
- PR #1 assigned `SENSITIVITY-EXCLUSION` to later operations without testable acceptance. SPEC-002 through SPEC-005 and BK-011/BK-015/BK-017/BK-018/BK-021/BK-022 now require positive-control inclusion and excluded-data omission from artifacts, diagnostics, logs, metrics, embeddings, and destination requests as applicable; lexical, embedding, planning, and adapter checks sit in the increments that can observe them.
- No accepted ADR was contradicted or superseded, and the explicit shared-scope marker did not introduce a cross-vault or authorization design requiring a new ADR.
