# BK-003 completion evidence

## Scope

Added JSON Schema 2020-12 contracts for the common decoded OKF frontmatter and all initial Bookie concept types: Project, Task, Document, Research, Decision, Activity, Evidence, and Person. Added a versioned positive fixture for each type plus required-field and shared-boundary negative fixtures.

## Red evidence

Before the schemas and fixtures existed, `node --test test/concept-schema.test.mjs` failed with exit code 1. The new contract test reported missing `schemas/bookie-common.schema.json` and `fixtures/concepts/1.0/{valid,invalid}` paths, demonstrating that the required common and type contracts did not exist.

## Review regression evidence

Review found that the original UTC timestamp pattern accepted impossible dates and times. After adding calendar-date, month, and clock-time negative fixtures—but before tightening the pattern—`node --test test/concept-schema.test.mjs` failed with exit code 1 because all three invalid timestamps unexpectedly passed. The schema now validates proleptic-Gregorian calendar boundaries, including leap years, and keeps the required UTC `Z` suffix.

## Acceptance notes

- Common metadata requires `type`, `title`, `status`, `generated`, and `bookie`; the lifecycle enum is independent from any Bookie workflow enum.
- All concepts require profile `1.0` and a prefixed, canonical uppercase ULID. Type-specific schemas require the fields assigned to each type in the accepted data model.
- Project, Task, and Decision validate their distinct workflow-state enums. Shared types retain the separation between lifecycle status, content-generation time, and creation, occurrence, or capture time.
- Evidence requires project, capture time, resource, lowercase SHA-256 digest, media type, and at least one supported concept.
- Common and `bookie` objects intentionally permit unknown fields so frontmatter extensions remain preservable under REQ-004 and ADR-0001. Relation vocabulary, target normalization, inverse checks, exact type-prefix mapping, resource containment, digest verification, and Git-base policy remain BK-004 or later work.

## Review

An independent disposable-workspace review found and verified the timestamp-boundary defect above. The corrected schema remains limited to decoded-frontmatter constraints and does not introduce YAML parsing, filesystem behavior, cross-file validation, or a closed frontmatter model.
