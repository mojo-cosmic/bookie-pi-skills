## Acceptance notes

- The schema fixes the manifest version at `1.0` and rejects unknown keys at the root and in nested `vault`, `policy`, and `policy.sensitivity` objects.
- Minimal, representative example, minimum-boundary, and maximum-boundary fixtures pass; every excluded class in a valid fixture is also declared.
- Negative fixtures cover missing required UID, empty required arrays, version type/value, canonical VLT ULID alphabet and 128-bit leading-symbol bounds, allowed-type enums and duplicates, sensitivity length/syntax/duplicates/reserved sentinels, and attachment integer bounds. Table-driven tests additionally omit every required root and nested property, reject an empty title, and exercise duplicates in every duplicate-free array.
- Evidence-root fixtures cover absolute, traversal, dot/empty-segment, backslash, glob, Windows drive, URI/colon, percent-encoded, and C0/C1-control boundaries. Adversarial tables cover U+2028/U+2029 before colon, percent, glob, traversal, and C0 values, reject a lone UTF-16 surrogate, and retain valid Unicode scalars. The schema asserts lexical validity only; containment, realpath/symlink behavior, and glob execution remain runtime responsibilities.
- `SENSITIVITY-ALLOWLIST` is a named, deferred SPEC-002/BK-007 runtime rule: only declared, non-reserved, non-excluded classes permit indexing, checkpointing, logging, or export; missing, reserved, undeclared, and excluded classes fail closed. JSON Schema is not credited with cross-array or record-policy enforcement.
- Attachment bounds apply to decoded numeric values. Precision-losing YAML numeric scalar text must be rejected by the eventual parser/runtime; the existing fractional decoded fixture remains covered, and OQ-002 is not resolved here.
- OQ-002, OQ-005, and OQ-007 remain unresolved.
