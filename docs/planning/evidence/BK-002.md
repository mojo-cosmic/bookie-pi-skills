# BK-002 completion evidence

## Scope

Defined the strict JSON Schema 2020-12 contract for the decoded profile 1.0 `bookie.yaml` manifest, added versioned valid/invalid JSON fixtures, and updated the example profile. Common metadata and concept schemas remain authoritative SPEC-001 artifacts deferred from BK-002 to BK-003. YAML parsing, runtime and cross-file policy, filesystem containment, glob execution, CLI, Pi, and service behavior remain out of scope for BK-002.

## Files and behavior

- `schemas/profile/1.0/bookie-config.schema.json` defines the strict decoded manifest contract and validator-portable lexical guards.
- `fixtures/profile/1.0/bookie-config/{valid,invalid}/` covers valid examples, boundaries, isolated UID/sensitivity failures, path attacks, structural failures, and numeric limits.
- `test/bookie-config-schema.test.mjs` meta-validates and compiles the schema, pins each invalid fixture to exact Ajv error locations, checks every typed location, and compares the complete example manifest with its decoded fixture.

- `package.json` and `package-lock.json` add Ajv 8 as the direct test dependency.

## Acceptance notes

- The schema fixes the manifest version at `1.0` and rejects unknown keys at the root and in nested `vault`, `policy`, and `policy.sensitivity` objects.
- Minimal, representative example, minimum-boundary, and maximum-boundary fixtures pass; every excluded class in a valid fixture is also declared.
- Negative fixtures cover missing required UID, empty required arrays, version type/value, canonical VLT ULID prefix, length, alphabet and 128-bit leading-symbol bounds, allowed-type enums and duplicates, isolated sensitivity syntax boundaries, sensitivity length/duplicates/reserved sentinels, and attachment integer bounds. Table-driven tests additionally omit every required root and nested property, reject wrong types at every typed location, reject an empty title, and exercise duplicates in every duplicate-free array.
- Evidence-root fixtures cover absolute, traversal, dot/empty-segment, backslash, the explicitly denied glob metacharacters, Windows drive, URI/colon, percent-encoded, and C0/DEL/C1-control boundaries. Adversarial tables cover U+2028/U+2029 before colon, percent, glob, traversal, and C0 values, reject a lone UTF-16 surrogate, and retain valid Unicode scalars. Evidence roots remain literal paths; containment, realpath/symlink behavior, and glob execution remain runtime responsibilities.
- `SENSITIVITY-EXCLUSION` traces directly to REQ-026. Runtime export, checkpoint, and indexing enforcement remains assigned to BK-011, BK-015, and BK-017 respectively; BK-002 does not settle missing, reserved, undeclared, or provider-authorized record behavior.
- Attachment bounds apply to decoded numeric values. Precision-losing YAML numeric scalar text must be rejected by the eventual parser/runtime; the existing fractional decoded fixture remains covered, and OQ-002 is not resolved here.
- OQ-002, OQ-005, and OQ-007 remain unresolved.

## Drift found and resolved

- `docs/architecture/data-model.md` already showed profile `1.0` while the example manifest and concepts still used `0.1`; this slice aligned the example to the accepted profile version.
- SPEC-001 originally named an unversioned `schemas/bookie-config.schema.json`; the delivered artifact is versioned under `schemas/profile/1.0/`, and the spec now records that migration explicitly.
- Review found that the first draft over-claimed glob rejection and promoted open sensitivity-policy direction beyond REQ-026. The final wording names the actual lexical boundary and limits the deferred runtime rule to the authoritative excluded-class requirement.
- No accepted ADR was contradicted or superseded.
