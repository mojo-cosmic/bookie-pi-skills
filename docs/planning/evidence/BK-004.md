# BK-004 completion evidence

## Scope

Defined profile 1.0 UID prefix/type mapping, normalized concept and Evidence resource path syntax, the relation object/vocabulary/inverse contract, stable cross-file rule codes, and materializable base/proposed policy fixtures. Production whole-vault and Git-base enforcement remains assigned to SPEC-002.

## Files and behavior

- `schemas/bookie-common.schema.json` now validates relation structure, the exact relation vocabulary, optional cached target UIDs, duplicate exact relations, bundle-absolute concept paths, and lexical Evidence resource paths.
- `schemas/types/*.schema.json` composes generic ULID syntax with the exact `PRJ`, `TSK`, `DOC`, `RSC`, `DSN`, `ACT`, `EVD`, and `PER` type prefixes.
- `docs/specs/001-canonical-ledger.md` defines manifest type allow-list enforcement, inverse semantics, allowed supersession types, immutable-reference path pinning, and eleven stable cross-file rule codes.
- `fixtures/policy/1.0/` contains schema-valid materializable base/proposed trees plus exact UTF-8, CRLF, changed, and binary resource bytes. Cases cover relation inverses, one-to-one and consolidated Decision replacement, Decision deletion/multiple replacements, immutable edit/deletion/rename, pinned project/relation/support target replacement by a different UID, resource byte change/deletion/escape/size/type, digest mismatch, missing support, duplicate UID, and target/UID mismatch.
- `test/concept-schema.test.mjs` covers the exact relation enum, every wrong known prefix for every type, path attacks and Unicode boundaries, relation fields, and portable regex end guards.
- `test/policy-contract.test.mjs` materializes and schema-validates every tree, evaluates the fixture contract, and verifies exact-byte digests. It is test-only and does not claim to implement the SPEC-002 runtime validator.

## Red evidence

Before the schema implementation, `node --test test/concept-schema.test.mjs` failed as intended:

```text
ℹ tests 282
ℹ pass 252
ℹ fail 30
```

Failures showed that every type accepted a wrong known prefix and that unknown/missing relation fields, duplicate relations, malformed target paths, invalid project/support paths, and traversal-bearing Evidence resources were accepted.

Before policy documentation and fixtures existed, `node --test test/policy-contract.test.mjs` failed three top-level tests for the missing UID/relation tables, missing policy fixture directories, and missing exact resource bytes. Review regressions also failed before adding complete materialized trees and isolated oversized/symlink/path-pinning cases.

## Review corrections

Independent review found that the first declarative policy facts were not executable enough, supersession type behavior was ambiguous, immutable references conflicted with unrestricted target renames, and several schema mutants survived. The final change:

- materializes complete schema-valid decoded records and deterministic Markdown bytes;
- evaluates every expected policy boundary in a test-only fixture oracle;
- limits supersession to Decisions and same-type Activity/Evidence corrections;
- path-pins targets referenced from merged immutable records;
- tests every wrong prefix, exact relation vocabulary, portable end guards, query/control/surrogate paths, CRLF/binary digests, resource limits, and symlink rejection;
- corrects architecture prose so it no longer claims current CI runtime enforcement.

## Acceptance demonstrated

- Reference tables fix all eight UID prefixes and all nine relation kinds with inverse requirements.
- JSON Schema rejects wrong type prefixes, malformed relation objects, unknown kinds, exact duplicates, unsafe/non-canonical concept references, and unsafe lexical Evidence paths while preserving unknown extension fields.
- Stable rule codes and executable contract fixtures cover manifest type allowance, UID uniqueness, project/target/support resolution, inverse mismatch, Decision supersession, Activity/Evidence immutability, resource containment/type/size, and exact-byte digest mismatch.
- Valid replacement fixtures retain immutable predecessors and add new incoming `supersedes` edges without requiring impossible edits to merged Activity/Evidence.
- Paths referenced by merged immutable records are explicitly pinned until a future profile defines portable alias or UID-fallback semantics.

## Assumptions and follow-ups

- JSON fixtures use deterministic flow-style YAML rendering only to supply exact Markdown bytes to the contract oracle; YAML parser selection remains OQ-002 and production parsing remains BK-006.
- Full Markdown vault fixtures, the profile reference, and compatibility/migration guidance remain BK-005.
- Production diagnostics and Git/filesystem enforcement remain BK-007 and BK-009.
- No accepted ADR was contradicted or superseded.
